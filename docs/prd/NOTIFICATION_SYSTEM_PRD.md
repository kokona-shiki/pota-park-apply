# POTA 公园申请系统 - 通知系统需求文档

## 1. 概述

本文档描述了 POTA 公园申请系统中通知系统的功能需求，旨在为用户提供及时、准确的信息推送服务，提升用户体验和系统运营效率。

## 2. 通知类型

系统需要支持以下四种通知类型：

### 2.1 公园申请状态变更通知
- **触发场景**：公园申请的状态发生变更时
- **通知对象**：申请人、相关审核员、POTA 地图代表
- **状态类型**：pending（待审核）、approved（已通过）、rejected（已拒绝）、pota_synced（已同步）
- **特殊规则**：
  - 申请提交时：通知审核员
  - 申请通过时：通知申请人；如果审核操作者不是 POTA 地图代表，则同时通知 POTA 地图代表
  - 申请拒绝时：通知申请人
  - POTA 同步完成时：通知申请人

### 2.2 用户管理操作通知
- **触发场景**：用户的角色、账号状态等被管理员修改时
- **通知对象**：被操作的用户
- **操作类型**：角色变更、账号禁用/启用、权限调整等

### 2.3 POTA 数据同步通知
- **触发场景**：POTA 数据同步任务完成或失败时
- **通知对象**：系统管理员、POTA 地图代表
- **同步类型**：数据导入、数据更新、同步失败等

### 2.4 呼号变更申请通知
- **触发场景**：呼号变更申请提交或审核结果产生时
- **通知对象**：申请人、系统管理员
- **状态类型**：申请提交、审核通过、审核拒绝

## 3. 通知接收方式

### 3.1 站内消息（网页显示）
- 用户登录后在网站内查看通知列表
- 支持实时推送或定时刷新获取新通知
- 通知列表按时间倒序排列

### 3.2 扩展接口（预留）
- 预留扩展接口，支持未来接入邮件、短信、微信等通知渠道
- 采用插件化设计，便于后续扩展

## 4. 通知内容

每条通知包含以下信息：

### 4.1 基本信息
- **标题**：简洁明了的通知标题（中文）
- **详细描述**：通知的具体内容说明（中文）
- **创建时间**：通知生成的时间戳
- **通知类型**：标识通知所属类型

### 4.2 关联信息
- **跳转链接**：点击通知可跳转到相关页面（如申请详情页、用户信息页等）
- **关联对象 ID**：如申请 ID、用户 ID 等，用于数据关联

### 4.3 状态管理
- **已读/未读状态**：支持标记已读和未读
- **状态变更方式**：
  - 用户点击通知查看详情时自动标记为已读
  - 用户手动点击"标记为已读"按钮
- **删除策略**：
  - 用户不可删除通知
  - 通知不会自动过期
  - 通知永久保留，仅通过用户操作改变已读状态

## 5. 通知范围

### 5.1 个人相关通知
- 用户只能看到与自己相关的通知
- 包括：自己的申请状态变更、自己的账号操作、自己的呼号变更等

### 5.2 全局通知
- 所有用户都能看到的系统级通知
- 包括：系统公告、重要通知等
- 只有系统管理员可以发布全局通知
- **通知类型**：
  - **站内信**：普通的通知消息，显示在通知列表和通知中心
  - **弹窗通知**：重要通知，以弹窗形式显示给用户
- **草稿功能**：
  - 系统管理员可以创建全局通知草稿
  - 草稿保存在草稿箱中，不会发送给用户
  - 草稿数量不限制
  - 草稿可以编辑、删除
  - 草稿可以发布为正式通知
- **发布流程**：
  - 系统管理员在全局通知编辑界面创建通知
  - 可以选择通知类型：站内信或弹窗通知
  - 可以保存为草稿、定时发布或立即发布
  - 发布后通知推送给所有用户
- **定时发布**：
  - 支持设置通知的发布时间
  - 到达指定时间后自动发布
  - 定时发布的通知在发布前可以取消或修改
- **撤回功能**：
  - 已发布的全局通知可以撤回
  - 撤回后用户不再能看到该通知
  - 撤回的通知可以重新编辑和发布
- **内容格式**：
  - 支持 Markdown 语法
  - 可以格式化文本、插入链接等

### 5.3 角色相关通知
- 特定角色用户能看到的专属通知
- 例如：系统管理员能看到 POTA 同步通知、POTA 地图代表能看到审核相关通知

## 6. 通知触发时机

| 触发时机 | 通知类型 | 通知对象 | 说明 |
|---------|---------|---------|------|
| 申请提交时 | 公园申请状态变更通知 | 审核员 | 通知审核员有新申请需要审核 |
| 申请通过时 | 公园申请状态变更通知 | 申请人、POTA 地图代表 | 通知申请人审核通过；如果审核操作者不是 POTA 地图代表，则同时通知 POTA 地图代表 |
| 申请拒绝时 | 公园申请状态变更通知 | 申请人 | 通知申请人审核拒绝 |
| POTA 同步完成时 | 公园申请状态变更通知 | 申请人 | 通知申请人已同步到 POTA |
| 用户角色变更时 | 用户管理操作通知 | 被操作用户 | 通知用户其角色或权限已变更 |
| POTA 同步完成时 | POTA 数据同步通知 | 系统管理员、POTA 地图代表 | 通知相关人员数据同步状态 |
| 呼号变更申请提交时 | 呼号变更申请通知 | 系统管理员 | 通知系统管理员有新的呼号变更申请 |
| 呼号变更审核完成时 | 呼号变更申请通知 | 申请人 | 通知申请人审核结果 |

## 7. 未读通知统计

### 7.1 显示位置
- 在页面顶部导航栏显示未读通知数量
- 使用红点或数字角标形式展示

### 7.2 统计规则
- 仅统计当前用户的未读通知数量
- 实时更新未读数量
- 点击通知或标记为已读后，未读数量相应减少

## 8. 优先级策略

- **不需要优先级分类**
- 所有通知按时间倒序排列
- 最新创建的通知显示在最前面

## 9. 数据库设计（初步）

### 9.1 通知表（notifications）
| 字段名 | 类型 | 说明 |
|-------|------|------|
| id | INTEGER | 主键，自增 |
| user_id | INTEGER | 接收通知的用户 ID（NULL 表示全局通知） |
| type | VARCHAR | 通知类型 |
| title | VARCHAR | 通知标题 |
| description | TEXT | 通知详细描述（支持 Markdown） |
| link_url | VARCHAR | 跳转链接 |
| is_read | BOOLEAN | 是否已读 |
| created_at | TIMESTAMP | 创建时间 |
| metadata | JSONB | 扩展信息（如关联对象 ID 等） |
| is_global | BOOLEAN | 是否为全局通知 |
| notification_mode | VARCHAR | 通知模式：normal（站内信）、popup（弹窗通知） |
| popup_dismissed | BOOLEAN | 弹窗是否已被用户关闭（仅弹窗通知有效） |
| status | VARCHAR | 状态：draft（草稿）、published（已发布）、withdrawn（已撤回） |
| published_at | TIMESTAMP | 发布时间 |
| published_by | INTEGER | 发布者用户 ID |
| scheduled_at | TIMESTAMP | 定时发布时间（NULL 表示立即发布） |

### 9.2 全局通知草稿表（notification_drafts）
| 字段名 | 类型 | 说明 |
|-------|------|------|
| id | INTEGER | 主键，自增 |
| title | VARCHAR | 通知标题 |
| description | TEXT | 通知详细描述（支持 Markdown） |
| link_url | VARCHAR | 跳转链接 |
| notification_mode | VARCHAR | 通知模式：normal（站内信）、popup（弹窗通知） |
| scheduled_at | TIMESTAMP | 定时发布时间（NULL 表示立即发布） |
| created_by | INTEGER | 创建者用户 ID |
| created_at | TIMESTAMP | 创建时间 |
| updated_at | TIMESTAMP | 更新时间 |

## 10. 前端界面设计

### 10.1 通知入口
- 顶部导航栏显示通知图标
- 未读数量角标
- 点击展开通知列表

### 10.2 通知列表
- 下拉式通知列表
- 显示最近 N 条通知（如 10 条）
- 每条通知显示：标题、时间、已读/未读状态
- 点击通知跳转到详情页并标记为已读
- 提供"全部标记为已读"按钮

### 10.3 弹窗通知
- **显示时机**：用户通过刷新进入页面、地址栏进入页面时弹出
- **显示规则**：
  - 如果有多个弹窗通知，只显示最新的一个
  - 用户关闭弹窗后，下次进入页面时不再弹出该通知
- **弹窗操作**：
  - 提供"确认"按钮：点击后标记为已读，不再弹出
  - 提供"不再提示"按钮：点击后标记为已读并设置 popup_dismissed = true
- **弹窗内容**：
  - 显示通知标题
  - 显示通知描述（支持 Markdown 渲染）
  - 如果有跳转链接，显示"查看详情"按钮

### 10.4 通知中心页面
- 独立的通知中心页面
- 分页显示所有通知
- 支持按类型筛选
- 显示完整的通知内容

### 10.5 全局通知编辑页面（仅系统管理员）
- **访问权限**：只有系统管理员可以访问
- **功能**：
  - 创建新的全局通知
  - 编辑已有草稿
  - 删除草稿
  - 发布草稿为正式通知
  - 直接发布通知（不保存为草稿）
  - 撤回已发布的全局通知
- **界面元素**：
  - 通知标题输入框
  - 通知描述输入框（支持 Markdown）
  - 跳转链接输入框（可选）
  - 通知模式选择：站内信/弹窗通知
  - 发布方式选择：立即发布/定时发布
  - 定时发布时间选择器（选择定时发布时显示）
  - 保存为草稿按钮
  - 发布按钮
- **草稿箱列表**：
  - 显示所有草稿
  - 显示草稿标题、创建时间、更新时间、通知模式、定时发布时间
  - 支持编辑、删除、发布操作

### 10.6 已发布全局通知管理（仅系统管理员）
- 显示所有已发布的全局通知
- 支持查看通知详情
- 支持查看通知的已读/未读统计
- 支持撤回已发布的全局通知
- 显示通知模式（站内信/弹窗通知）

## 11. 技术要求

### 11.1 后端
- 使用 Zod 进行类型验证
- 遵循现有的 API 响应格式：`{code, message, data}`
- 创建通知服务模块
- 实现通知创建、查询、标记已读等接口

### 11.2 前端
- 使用 MUI 组件库
- 遵循 MUI 设计规范
- 实现通知图标、通知列表、通知中心等组件
- 实现未读数量实时更新

### 11.3 数据库迁移
- 创建数据库迁移脚本
- 添加通知表及相关索引
