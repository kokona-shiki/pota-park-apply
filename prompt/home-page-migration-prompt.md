# 首页数据获取与搜索功能需求确认

## 1. 数据来源确认

1. 系统内已上传POTA的公园数据是否都存储在`park_applications`表中？
目前是的

2. 这些公园的状态是否都是`pota_synced`？
不是，只有成功同步的公园才会有`pota_synced`状态

3. POTA ID是否都存储在`pota_notes`字段中，格式是否统一为`POTA ID: CN-XXXX`？
这个需要你检查后端代码，理论上只要已经上传了 POTA 的公园，以及从 POTA 导入的公园，就一定有 POTA_ID

4. 是否需要包含其他表的数据？
理论上不需要，因为首页只需要显示公园的基本信息

## 2. 搜索功能确认

1. POTA ID搜索是否需要严格匹配`CN-XXXX`格式？
不是，用户仅输入数字也可以搜索到

2. 中文拼音搜索是否需要支持：

   * 全拼（如"beijing"）

   * 首字母缩写（如"bj"）

   * 部分拼音（如"bei"）

都要支持

3. 搜索是否需要实时更新结果，还是需要用户点击搜索按钮？
实时更新解决过

4. 搜索结果是否需要高亮显示匹配的关键词？
是的

## 3. 分页功能确认

1. 默认每页显示多少条数据？
默认每页 20 条
2. 是否需要支持自定义每页显示数量（如30、50、100）？
支持：20/50/100
3. 分页方式：
   * 后端分页（推荐，适合大数据量）✅
   * 前端分页（适合小数据量）

4. 是否需要显示总页数和总条数？
是的

## 4. 数据展示确认

1. 首页需要展示哪些字段？（目前显示：编号、名称、网格、尝试次数、激活次数、QSO数量）
这一期只需要展示编号、名称、网格、省份、公园类型

2. 是否需要支持按某个字段排序？
是的

3. 是否需要在首页显示公园的详细信息，还是需要跳转到详情页？
跳转到详情页

4. 是否需要添加其他交互功能？
不需要

## 5. 性能要求确认

1. 预计系统内已上传POTA的公园数量有多少？
目前是 2000 以下

2. 搜索响应时间要求（如<1秒）？
<1秒

3. 页面加载时间要求？
300ms 以内


## 6. 其他需求确认

1. 是否需要考虑权限控制，比如某些用户只能看到特定公园？
在首页不需要，即使是未登录用户，也可以访问首页的数据

2. 是否需要添加数据导出功能？
这个需求不需要

3. 是否需要添加筛选功能（如按省份、类型筛选）？
需要添加按照省份筛选，以及按照公园类型筛选

4. 是否需要支持多语言？
不需要
